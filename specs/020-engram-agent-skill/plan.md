# Implementation Plan: engram Agent Skill

**Branch**: `020-engram-agent-skill` | **Date**: 2026-07-29 |
**Spec**: [spec.md](./spec.md)

**Input**: [Feature specification](./spec.md) and the Phase 0 decisions in
[research.md](./research.md)

## Summary

交付一个位于 `skills/engram/` 的开放格式 Agent Skill，用简洁的 MCP-first 决策流程编排
engram 已有的长期记忆操作，并在 MCP 不可用时诚实回退到现有 CLI。Skill 只维护一份正文，
详细 MCP、CLI 和安装材料按需加载；`skills@1.5.20` 从预声明、不可变的 Git release tag 把
同一 package 安装到 Claude Code、Codex 与 OpenCode 的项目或个人作用域，默认预先披露目标
路径并保留人工确认。

实现以 TDD 建立格式 validator、真实 MCP/CLI surface contract tests 和隔离安装矩阵，再用
with-skill/without-skill 行为评估与正负触发集迭代正文。产品入口共享一条 canonical 安装命令；
发布前必须在三个真实客户端分别完成发现和显式调用 smoke。引擎、adapter 公共语义和默认离线
行为保持不变。

## Technical Context

**Language/Version**: GitHub-Flavored Markdown、受限 YAML frontmatter、JSON；
Node.js 24 标准库用于 validator/install smoke；Go 1.25 仅用于现有 adapter 的契约测试

**Primary Dependencies**: Agent Skills open specification；固定下载期安装器
`skills@1.5.20`（要求 Node.js `>=22.20.0`、npx、Git）；现有
`github.com/modelcontextprotocol/go-sdk` in-memory transport；无新增 skill 运行时依赖

**Storage**: Git 跟踪的 `skills/engram/` 文本包和验证 fixtures；安装后为项目或用户 skills
目录中的 copy/symlink；不新增数据库或远程服务

**Testing**: Node 内建 test runner + 无依赖 package validator；隔离 HOME/XDG/npm/temp 的
安装矩阵；`mcpserver` 和 `cmd/engram` 包内 Go contract tests；现有 MCP/CLI parity、
namespace/isolation 与 offline tests；20+ trigger evals；with-skill/without-skill benchmark
和 human review viewer；三个真实客户端的 release smoke；docs validator 和全量
`CGO_ENABLED=0` build/test/vet；需要 agent inference 的评估只使用本地或维护者已有的
零增量费用授权

**Target Platform**: Claude Code、Codex 和 OpenCode 当前 stable；Linux/macOS 的 symlink 或
copy，Windows/受限文件系统的 copy fallback；其他 Agent Skills consumers 自行兼容

**Project Type**: 现有 pure-Go engine 之上的纯 skill/distribution/documentation adapter
feature；不新增服务或产品算法

**Performance Goals**: 一个 remote command 能选择三端；除目标路径告知、安装方式、写入确认与 client
reload 外无需手工编排；每端成功后只发现一个同版本 skill；`SKILL.md` <=500 行且
`engram-body-token-estimate-v1` <=5,000；description <=1,024 字符；安装后调用不依赖
Node/npm/network

**Constraints**: canonical body 数量为 1；远程发布必须固定 installer version 与在候选内容
冻结前由 skill version 派生的 immutable `engram-skill-v<version>` release tag；package identity 使用
`engram-package-sha256-v1`；默认命令必须预警同名目标且保留写入确认；MCP-first、
single-surface、single-namespace；
普通聊天不写入；ingest/curate 显式且需 LLM；secret 仅走既有环境变量；不修改
`memory/ embedding/ provider/ store/ internal/`；不运行 LoCoMo、不配置 metered provider，
agent eval/smoke 的新增模型费用为 0

**Scale/Scope**: 1 个 skill package、3 个 clients、2 个 scopes、2 种安装模式、5 个常驻 +
1 个条件 MCP tool、11 个 CLI command、11 个 memory intents、至少 12 个行为 eval 和
20 个正负 trigger eval

## Constitution Check

| 原则 | 设计前判定 | 依据 |

## Phase 0: Research

[research.md](./research.md) 已冻结以下决策并记录 alternatives：

1. `skills/engram/SKILL.md` 是唯一 canonical body，portable frontmatter 只含 name/description。
2. Claude Code 使用 `.claude/skills`，Codex/OpenCode 共用 `.agents/skills`；三端显式调用与
   reload 契约分别记录，不承诺 OpenCode V2 行为。
3. 远程入口固定 `skills@1.5.20` 和在最终 package 冻结前由 skill version 派生的 immutable
   `engram-skill-v<version>` tag；先写 literal tag、再形成候选提交、最后由维护者授权发布，
   避免 commit SHA 自引用。
4. 默认预先列出标准目标并保留上游安装方式/写入确认；`-y` 只表示用户已明确授权
   managed replacement，不能依赖上游 global overwrite 摘要发现所有冲突。
5. 无 Node/离线时从同一 package 手动 copy/symlink；skill 使用期无安装器或网络依赖。
6. 主 skill 只含决策和安全规则，MCP/CLI/install 资料一层按需披露。
7. MCP 真实集合为 5 always + conditional ingest；CLI 真实集合为 11，包含后来交付的 curate。
8. 重叠 intent MCP-first；CLI-only 切面必须确认 data dir/namespace，禁止双写或自动合并。
9. 默认 namespace、合法式、LLM、offline、secret 和内容预算继承 adapter 真相。
10. 验证分为 package、runtime contract、isolated install、real-client discovery、
    behavior/trigger evaluation 五层；package 使用冻结的 digest/token 算法。
11. 安装正本随 package 分发，README/docs 命令由 validator 防漂移；不扩展 CLI help surface。
12. engine diff 为空，以 adapter invariants 取代无归因价值的 LoCoMo。
13. `skills-ref` 只有在准确版本已 pin/cache 时作为 advisory；缺失不阻断，实际失败必须修复
    或以当前开放规范证成版本 incompatibility，仓库 validator 是 engram 权威门。
14. agent eval/smoke 只允许 local 或 existing-flat-rate，并记录零增量费用；维护者 review
    必须给出显式 disposition。

Phase 0 结束条件已满足：每项都有 rationale/alternatives，安装器覆盖语义的冲突已通过安全
默认命令和 spec 修正收口，无 `NEEDS CLARIFICATION`。

## Implementation Strategy

1. **Validator first**：先写失败 fixtures 和 Node tests，再实现最小 package validator。
2. **Manifest before prose**：创建 `contract.json`，让两个 adapter package tests 对照真实
   `tools/list`/`knownCommands`，关闭过期名字风险。
3. **Canonical package draft**：按 routing contract 写精简 `SKILL.md` 与三份 references，
   加 license 和 eval schemas。
4. **Installer matrix**：在完全隔离的 child environment 用 local source 验证三端、两 scope、
   mode、重装、冲突取消和恢复；remote URL 留到预声明 release tag 发布后验证。
5. **Behavior iteration**：先验证 local/existing-flat-rate 零增量费用路径，再让 with-skill 和
   baseline 同批运行，客观 grade、benchmark、analysis 和 static viewer 交给维护者给出显式
   disposition；`changes-requested` 必须迭代到最终批准，再用 held-out trigger eval 优化
   description。
6. **Docs and CI**：同步三处 quick command、纠正 CLI help 漂移、增加 Node/contract/install
   gates，保持 package install reference 为详细正本。
7. **Release proof**：先选择未使用的 release tag 并写入最终 package/docs，验证并形成候选
   commit；经维护者授权把 tag 发布到该 commit 后，核对 tag/commit/digest，再执行 exact remote
   command、三个真实 client 的 project/user discovery 和组合 smoke，最后完成 validation report。

每步开始前重新读取相关文件和 git status；README/docs 集成前再次核对 sibling worktree，
发现重叠时停止而不是覆盖。
