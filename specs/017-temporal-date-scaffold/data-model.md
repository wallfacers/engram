# Phase 1 Data Model: 确定性日期脚手架

**Feature**: 017-temporal-date-scaffold | **Date**: 2026-07-27

本 feature **不引入任何持久化实体**——不建表、不改 schema、不写库。
以下全部是**进程内的中间值**,生命周期仅限于构造一次答题上下文。
这一点本身是宪法 II 合规的一部分:脚手架不在引擎的数据模型上留下任何痕迹。

---

## 实体

### E-1:`retrievedMemory`(既有,不改)

脚手架的**输入单元**。定义在 `cmd/locomo-bench/runner.go:470-476`,本 feature **不修改它**。

| 字段 | 类型 | 脚手架怎么用 |
|---|---|---|
| `Name` | string | 不用 |
| `Content` | string | 相对表达解析的扫描对象(D-3) |
| `EventDate` | string(`"2006-01-02"` 或 `""`) | **主日期来源**;空 = 该条不进 TIMELINE |
| `Recorded` | string | **不用作日期锚**(D-3:记录时间 ≠ 事件时间) |
| `SourceSessionID` | string | 不用 |

> **不变量 I-1**:脚手架**只读**输入记忆,不修改、不重排、不过滤原列表。
> 正文 `RETRIEVED MEMORIES` 段落在开关开启前后必须完全一致——
> 脚手架是**追加**,不是**改写**。

### E-2:`timelineEntry`(新增,进程内)

一条**有可解析日期**的记忆在 TIMELINE 中的呈现。

| 字段 | 类型 | 约束 |
|---|---|---|
| 序号 | int | 从 1 连续递增,不跳号 |
| 日期 | `time.Time` | 由 `EventDate` 解析而来,或由相对表达推导 |
| 日期粒度 | 枚举(day / month / year) | 决定呈现格式与算术精度上限 |
| 来源标记 | 枚举(原生 / 推导) | **必须可区分**(FR-004) |
| 对应记忆的正文序号 | int | 指回 `RETRIEVED MEMORIES` 中的编号,使模型能对回原文 |

> **不变量 I-2**:`timelineEntry` 的日期**永不为零值**。
> 无法确定日期的记忆根本不生成条目(而不是生成一个零值条目)。
>
> **不变量 I-3**:来源标记为"推导"的条目,其锚**必须**是该条记忆自己的 `EventDate`。
> 不得使用其他记忆的日期、`Recorded`、或任何外部时间作锚。

### E-3:`interval`(新增,进程内)

两个 `timelineEntry` 之间**预先算好**的时间跨度。

| 字段 | 类型 | 约束 |
|---|---|---|
| 起点序号 / 终点序号 | int, int | 均须指向存在的条目;起点 ≤ 终点 |
| 跨度值 | 结构化(天数 / 月数 / 年数) | 按两端点中**较粗**的粒度计算 |
| 精度标记 | 枚举(精确 / 约略) | 端点粒度不足时为"约略" |

> **不变量 I-4**:跨度的精度**不得高于**其两个端点中较粗的那个。
> 例:端点为"2023 年 5 月"(月粒度)与"2023-07-21"(日粒度)→ 跨度只能给"约 2 个月",
> **不得**给"74 天"。这是 spec Edge Cases「绝不补零假装精确」的形式化。
>
> **不变量 I-5**:候选条目 <2 时,`interval` 集合**必须为空**。
> 不得凭单个端点臆造第二个端点。

### E-4:`timelineBlock`(新增,进程内)

`timelineEntry` 有序集合 + `interval` 集合的整体呈现,即最终注入答题上下文的那段文本。

> **不变量 I-6(确定性)**:`timelineBlock` 是其输入记忆切片的**纯函数**。
> 相同输入 → 逐字节相同输出。禁止随机数、`time.Now()`、map 迭代顺序参与任何决策。
>
> **不变量 I-7(空块省略)**:条目数为 0 时,块**整体不输出**——
> 不输出空标题、不输出占位符。此时答题上下文与开关关闭时**逐字节相同**。
>
> **不变量 I-8(不臆造)**:块中出现的每一个日期,要么直接来自某条记忆的 `EventDate`,
> 要么由 I-3 规定的锚推导而来。**不存在第三种来源。**

### E-5:`answerRegimeFingerprint`(既有,扩展)

标识一次评测配置的字符串,定义在 `cmd/locomo-bench/main.go:1218-1230`。
本 feature 在开关开启时**追加**一个标记(具体记号见 [contracts/](./contracts/scaffold-contract.md))。

> **不变量 I-9**:开关关闭时 fingerprint **逐字节不变**(与今天相同),
> 开启时**必然不同**。这保证两种口径的 run 不会被 `run dir regime` 校验静默混用
> ——该校验已在 `main.go:1196-1215` 实现,会在 regime 不匹配时直接报错拒跑。

## 状态与流程

脚手架**无状态**。每题独立走一遍:

```
输入:本题的 []retrievedMemory(已检索、已截断到 top-k)+ category + 开关
  │
  ├─ 开关关 或 category ≠ temporal ──────────────→ 返回空串(上下文逐字节不变)
  │
  └─ 否则
       ├─ 逐条读 EventDate;空则跳过该条(记忆本身仍在正文中)
       ├─ 对有日期的条目:扫 Content 找窄集合内的相对表达,以本条日期为锚推导(失败则跳过推导)
       ├─ 按日期升序排序(同日保持原检索顺序 —— 稳定排序,确定性)
       ├─ 连续编号
       ├─ 条目数 ≥2 → 计算首尾跨度(+ 契约规定的相邻跨度),按 I-4 定精度
       └─ 条目数 = 0 → 返回空串(I-7)
  │
输出:timelineBlock 文本(或空串)
```

> **不变量 I-10(排序稳定性)**:同日期多条记忆的相对顺序 = 它们在输入中的顺序。
> 不得引入次级排序键(如按内容字典序)——那会让呈现顺序与检索排名脱钩,
> 且是一个无谓的额外决策点。

## 与既有数据的关系

| 既有结构 | 关系 |
|---|---|
| `memory.Result`(引擎公开类型) | **只读**,经 `toMemories` 转换后使用;引擎侧零改动 |
| `RETRIEVED MEMORIES` 正文段 | **不改**;TIMELINE 追加在其后(D-4) |
| system prompt 常量(`forceTemporalAnswerPrompt` 等) | **不改**;脚手架活在 user message 侧,与 prompt 常量正交 |
| `regime.json` 口径校验 | 复用既有机制,仅扩展 fingerprint 字符串(I-9) |
| 存储 schema / migrations | **完全不涉及** |
