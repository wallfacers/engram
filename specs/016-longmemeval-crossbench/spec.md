# Feature Specification: LongMemEval 子集先行 · 跨 benchmark 复现 coverage≠answer

**Feature Branch**: `016-longmemeval-crossbench`

**Created**: 2026-07-26

**Status**: Draft

**Input**: [归档设计](../../docs/archive/designs/2026-07-26-longmemeval-subset-design.md)（brainstorming 逐段确认，唯一事实来源）

## 背景与目的

评测可靠性论文提纲的 **RQ6「结论能否从 LoCoMo 外推到 LongMemEval」** 当前状态为
「engram 一手结果为空」，并带硬约束：两个 benchmark 至少共享一条可复现结论，否则
外推范围收窄到 LoCoMo。

同时 LoCoMo 侧已连续判死六个提升方向，确认接近架构上限。因此本特性**换战场做方法学
复现，不追分**：验证「证据覆盖不等于答对」与「检索侧/答题侧分账」是否在第二个
benchmark 上同向成立。

**证伪与复现同等有价值**：若结论不成立，说明既有结论是 benchmark-specific，战略应
转回检索侧。判据必须在测量前写死，防止事后为了「复现成功」而调整判据。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 让 LongMemEval 可被诚实测量（Priority: P1）

维护者要在 LongMemEval 上得到任何可信数字之前，必须先有一把**被验证过的证据尺子**。
当前评测工具读不进真实数据集（题型名不匹配直接报错），即使绕过该错误，会话时间信息
会全部塌缩、证据标记完全未被读取，导致证据覆盖率恒为零——**没有尺子，后续所有数字
都不可信**。

本故事交付：评测工具能正确读入真实数据集，并证明其证据覆盖率读数是真实的。

**Why this priority**: 这是不可跳过的前置门禁。尺子不可信则 US2/US3 全部作废，
本特性到此为止。它也是唯一一个**零远程依赖、可立即执行**的切片。

**Independent Test**: 在完美证据数据集的 30 题小样本上运行只读的覆盖诊断（不产生
任何答题或判分模型调用），得到的精确证据覆盖率应达到 0.95 以上——因为该数据集按
构造不含任何干扰项，覆盖率若不接近满分，只可能是读取或计量有误。

**Acceptance Scenarios**:

1. **Given** 真实数据集含 `single-session-preference` 题型，**When** 评测工具读入，
   **Then** 全部 500 题成功加载，无题型相关错误。
2. **Given** 一道题的各会话带有互不相同的日期，**When** 评测工具读入，**Then** 每个
   会话被赋予其对应日期，且这些日期互不相同。
3. **Given** 某题的会话数量与日期数量不一致，**When** 评测工具读入，**Then** 明确
   报错并终止，**不得**静默回落到任何默认日期。
4. **Given** 某题的部分消息被标记为答案证据，**When** 评测工具读入，**Then** 恰好
   这些消息成为该题的黄金证据，未标记的消息不成为证据。
5. **Given** 某题不含任何证据标记（全集中共 21 题），**When** 计量覆盖率，
   **Then** 该题被判为不可评分并排除出统计，而非计为零覆盖。
6. **Given** 完美证据数据集的 30 题小样本已建立记忆库，**When** 运行只读覆盖诊断，
   **Then** 精确证据覆盖率 ≥ 0.95，且答题模型调用次数与判分模型调用次数均为 0。

---

### User Story 2 - 完美证据下的答题上限（Priority: P2）

维护者需要知道：**当证据完全正确、且不含任何干扰项时**，系统在这个 benchmark 上
能答对多少。这个数字是该 benchmark 上的答题侧天花板，也是解释真实检索臂成绩的参照。

**Why this priority**: 它本身即一手数据（此前为空），并且在承诺高成本的真实检索臂
之前，先在 500 题规模上验证整条流水线跑得通。其语料规模仅为 LoCoMo 全量的约 1.86 倍，
成本可控。

**Independent Test**: 在完美证据数据集全 500 题上完成建库与答题，得到总体正确率与
分题型正确率，无需真实检索臂即可解读。

**Acceptance Scenarios**:

1. **Given** 完美证据数据集全 500 题，**When** 完成建库，**Then** 每题记忆库的向量
   行数与应有行数一致（不允许存在未向量化的条目）。
2. **Given** 建库完成，**When** 运行答题与判分，**Then** 产出总体正确率、分 6 种
   题型的正确率，以及逐题结果记录。
3. **Given** 结果已产出，**When** 撰写报告，**Then** 报告明确标注数据集为
   「LongMemEval-oracle（cleaned 版）」并声明其为**独立新基线**，不替代既有 LoCoMo 基线。

---

### User Story 3 - 真实检索下的分账与最终判决（Priority: P3）

维护者需要在真实检索条件下，按逐题证据覆盖率分桶计算各桶正确率，得到**条件增益**
（全覆盖正确率 − 零覆盖正确率），并与 LoCoMo 已确立的 35.2pp 对照，据此判定
「覆盖不等于答对」是否跨 benchmark 复现。

**Why this priority**: 这是本特性的最终结论，但依赖 US1 的尺子，且成本最高
（语料约为 LoCoMo 全量的 8.4 倍）。

**Independent Test**: 在真实检索数据集的分层抽样 100 题上完成建库、检索、答题、判分，
输出各覆盖桶的题数与正确率、条件增益、检索侧当量与答题侧当量，并对照预先写死的判据
给出「复现 / 证伪 / 无法判定」三选一的结论。

**Acceptance Scenarios**:

1. **Given** 真实检索数据集全 500 题，**When** 执行分层抽样，**Then** 抽出 100 题且
   各题型配额为 multi-session 27、temporal-reasoning 27、knowledge-update 15、
   single-session-user 14、single-session-assistant 11、single-session-preference 6；
   抽中的题目标识列表随产物落盘，重复执行结果完全一致。
2. **Given** 抽样子集已建库，**When** 检查向量完整性，**Then** 向量行数与应有行数一致。
3. **Given** 完成答题（重复 3 次），**When** 按逐题证据覆盖率分桶，**Then** 输出
   全覆盖 / 部分覆盖 / 零覆盖三桶的题数与正确率。
4. **Given** 各桶结果已得出，**When** 某桶题数少于 20，**Then** 该桶结论标记为
   「不可判」，不得报出点估计作为结论。
5. **Given** 条件增益与两侧当量已算出，**When** 对照判据，**Then** 结论只能是
   「复现」「证伪」「无法判定」三者之一，判据不得在事后调整。
6. **Given** 最终结论已得出，**When** 归档，**Then** 判决写入本特性专属台账文件，
   并回填论文提纲中 RQ6 的状态；**不得**写入正被其他工作并发修改的既有杠杆台账。

---

### Edge Cases

- **证据标记缺失**：21/500 题不含任何证据标记 → 判为不可评分并排除，而非计为零覆盖。
- **会话数与日期数不一致**：硬报错终止，不静默回落——静默回落正是本特性要修复的缺陷本身。
- **向量回填不完整**：记忆向量化受有界队列限制，单次建库可能静默丢弃部分条目，
  导致语义检索部分失明且系统按设计不报错 → 必须以硬断言拦截，不得靠人工目视。
- **覆盖桶样本过小**：任一桶题数 < 20 → 标记不可判。
- **判决落在灰区**：条件增益落在复现区间与证伪区间之间 → 报「无法判定」，
  **不得**向任一侧四舍五入。
- **完美证据臂与真实检索臂的差异含混杂**：两者除覆盖率外还相差约 24 倍的干扰项密度，
  二者在该 benchmark 设计中天然绑定 → 该对比只能作为上界报告，不得作因果结论。
- **远程算力不可用**：US1 全程不依赖远程算力；US2/US3 需排队，排队不得成为 US1 的阻塞。

## Requirements *(mandatory)*

### Functional Requirements

**数据读取（US1）**

- **FR-001**: 系统 MUST 支持数据集中出现的全部 6 种题型，包含
  `single-session-preference`；同时 MUST 保持对既有题型名的兼容。
- **FR-002**: 系统 MUST 从数据集提供的会话日期序列中，按位置为每个会话赋予其对应日期。
- **FR-003**: 当会话数量与日期数量不一致时，系统 MUST 报错终止，MUST NOT 使用任何
  默认日期继续。
- **FR-004**: 系统 MUST 为每条消息赋予稳定且可被证据引用的轮次标识，其形式 MUST 与
  既有 benchmark 的轮次标识同构，使既有覆盖计量、归因追踪逻辑无需修改即可复用。
- **FR-005**: 系统 MUST 将被标记为答案证据的消息、且仅将这些消息，作为该题的黄金证据。
- **FR-006**: 系统 MUST 保留数据集提供的逐会话标识，用于数据自洽性校验与产物追溯。
  **会话级召回不依赖该字段** —— 它由 FR-004 的轮次标识中所含的会话序自动得出。
  （本条初稿曾要求「用证据会话标识集合做会话级召回计量」，经调研发现该机制已由既有
  代码路径自动成立，不需要新字段；此处按调研结论修正，避免引入无人使用的字段。）
- **FR-007**: 对不含任何证据标记的题目，系统 MUST 使其走既有的「不可评分」路径，
  MUST NOT 为其构造替代证据。

**尺子验证门（US1）**

- **FR-008**: 系统 MUST 提供在完美证据数据集小样本上运行的只读覆盖诊断，且该诊断
  MUST NOT 产生任何答题或判分模型调用。
- **FR-009**: 该诊断 MUST 报告精确证据覆盖率；覆盖率 < 0.95 时，本特性 MUST 停止，
  MUST NOT 进入后续任何阶段。

**建库完整性门（US2、US3）**

- **FR-010**: 每次建库完成后，系统 MUST 断言记忆向量行数等于应有行数；不相等时
  MUST 报错，MUST NOT 继续评测。

**完美证据臂（US2）**

- **FR-011**: 系统 MUST 在完美证据数据集全 500 题上完成建库、检索、答题与判分。
- **FR-012**: 系统 MUST 输出总体正确率、分题型正确率与逐题结果记录。

**真实检索臂（US3）**

- **FR-013**: 系统 MUST 按题型比例分层抽样 100 题，配额固定为
  27/27/15/14/11/6（multi-session / temporal-reasoning / knowledge-update /
  single-session-user / single-session-assistant / single-session-preference）。
- **FR-014**: 抽样 MUST 可复现——固定种子，且抽中的题目标识列表随产物落盘。
- **FR-015**: 系统 MUST 在抽样子集上重复答题 3 次以抑制方差。
- **FR-016**: 系统 MUST 按逐题证据覆盖率将题目分为全覆盖、部分覆盖、零覆盖三桶，
  并输出各桶题数与正确率。
- **FR-017**: 系统 MUST 计算条件增益（全覆盖正确率 − 零覆盖正确率）、检索侧当量
  （零覆盖题数 × 条件增益）与答题侧当量（全覆盖仍答错的题数）。
- **FR-018**: 任一桶题数 < 20 时，系统 MUST 将该桶结论标记为「不可判」。

**判决与报告（US3）**

- **FR-019**: 判据 MUST 在测量前固化：条件增益落在 20–50pp 且检索侧当量 < 答题侧
  当量 ⇒ 复现；条件增益 > 60pp 或检索侧当量 > 答题侧当量 ⇒ 证伪；其余 ⇒ 无法判定。
- **FR-020**: 报告 MUST 明示所用数据集版本与子集规模，MUST NOT 简称为全量。
- **FR-021**: 报告 MUST 记录该数据集官方已废弃旧版本这一事实，并声明本次数字与基于
  旧版本发表的第三方数字不可直接对比。
- **FR-022**: 本 benchmark 的成绩 MUST 声明为独立新基线，MUST NOT 替代或覆盖既有
  LoCoMo 基线。
- **FR-023**: 完美证据臂与真实检索臂的正确率对比 MUST 标注含干扰项密度混杂，
  MUST NOT 作为因果结论呈现。
- **FR-024**: 判决 MUST 写入本特性专属台账文件，并回填论文提纲中 RQ6 的状态；
  MUST NOT 写入正被其他工作并发修改的既有杠杆台账。

**边界约束**

- **FR-025**: 本特性 MUST NOT 修改记忆引擎（存储、检索、抽取、策展、嵌入）的任何
  代码；改动范围限于评测工具。
- **FR-026**: 本特性 MUST NOT 引入官方分题型判分口径、弃答子集、超大规模数据集变体、
  数据集第二版，以及「强制注入黄金证据」的干预臂。

### Key Entities

- **题目（Question）**：一道 LongMemEval 问题，含问题文本、标准答案、题型、提问时间，
  以及一份专属的会话堆（haystack）。不同题目的会话堆互不共享。
- **会话堆（Haystack）**：该题可检索的全部会话；每个会话含一组消息与一个发生日期。
  完美证据版本中它恰好等于证据会话集合；真实检索版本中证据会话仅占其约 4%。
- **证据标记（Evidence Marker）**：消息级的「含答案」标记。它同时支撑精确消息召回与
  会话级召回 —— 后者由消息所属的会话序直接得出，不需要额外的会话标识集合。题级的
  证据会话标识集合仅作数据自洽性校验之用。
- **评测臂（Arm）**：一次完整的建库—检索—答题—判分配置。本特性有两个：完美证据臂
  与真实检索臂。
- **覆盖桶（Coverage Bucket）**：按逐题证据覆盖率划分的题目分组（全覆盖 / 部分覆盖 /
  零覆盖），是分账分析的基本单位。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 真实数据集的全部 500 道题目均可被评测工具成功读入，读入失败数为 0。
- **SC-002**: 同一题目内不同会话被赋予的日期互不相同（当数据集为其提供了不同日期时），
  日期塌缩为单一值的题目数为 0。
- **SC-003**: 完美证据数据集小样本上的精确证据覆盖率 ≥ 0.95，且该测量过程中的答题
  模型调用数与判分模型调用数均为 0。
- **SC-004**: 每次建库后，未向量化的记忆条目数为 0。
- **SC-005**: 完美证据臂产出覆盖全部 500 题的正确率结果，缺失题目数为 0。
- **SC-006**: 真实检索臂的抽样在重复执行下产出完全相同的题目集合。
- **SC-007**: 分账分析产出三个覆盖桶的题数、正确率与条件增益；样本数不足 20 的桶被
  显式标记为不可判，数量如实报出。
- **SC-008**: 最终判决为「复现 / 证伪 / 无法判定」之一，且所依据的判据与测量前记录的
  判据逐字一致。
- **SC-009**: 记忆引擎代码改动量为 0 个文件。
- **SC-010**: 论文提纲中 RQ6 的状态由「一手结果为空」更新为本次结论。

## Assumptions

- 数据集采用官方当前推荐的 cleaned 版本（原版已被官方废弃，废弃理由为噪声会话干扰
  答案正确性）；因此本次数字与基于原版发表的第三方数字不可直接对比，此事实如实记录
  而非回避。
- 判分沿用本仓既有的对齐口径，以保证与全部既有 LoCoMo 判决同源、可跨 benchmark 比较
  自身结论；官方分题型判分口径列为未来工作。
- 完美证据版本按构造不含干扰项（已核实全部 500 题的会话堆恰好等于其证据会话集合），
  因此其覆盖率接近满分是合理预期，可用作尺子的验证基准。
- 真实检索臂的语料规模约为既有 LoCoMo 全量的 8.4 倍，完美证据臂约为 1.86 倍；建库
  成本按实际用量计量并记录，不预先估算。
- 远程算力当前被其他工作占用，US2/US3 需排队；US1 全程使用本地算力与小额调用，
  不受排队影响。
- 既有覆盖计量与归因追踪逻辑在证据形式同构后可原样复用，无需为本 benchmark 另写一套。
