# Feature Specification: Adaptive Retrieval Depth (自适应检索深度)

**Feature Branch**: `worktree-040-adaptive-topk-dedup`

**Created**: 2026-08-13

**Status**: Draft

**Input**: User description: "缩减检索 top-k 预算——自适应截断 + 冗余去重，预算下提质，不破坏现有分数"

> **Scope 修正（2026-08-13）**：原描述中的「冗余去重」方向在 spec 定稿前经历史 verdict 审计后**移出 scope**（见下）。本 feature 只做「自适应检索深度」（per-query 决定检索证据量），且以「零成本诊断」作为生死前提。worktree/目录名保留 `-dedup` 后缀仅为历史标识，不代表仍包含去重。

## Clarifications

### Session 2026-08-13

- Q: 冗余去重如何判定「近似重复」证据（文本重叠 / 语义向量 / 混合）？→ A: 三条路径均已在历史 feature 中证伪，方向整体移出 scope —— 024 `write_dedup`（文本 trigram Jaccard 去重）−0.91pp 且几乎不触发（21,860 判定仅 20 抑制）；025 `semantic-episode-cluster`（语义聚合）−7.7pp；026 query-time 剪枝编译 −4.5pp。共同结论：LoCoMo 需要「逐证据命中覆盖」而非「去重/聚合/压缩」。本 feature 不做去冗余。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 零成本诊断：证明「缩减深度不丢证据」这个前提成立 (Priority: P1)

评测维护者在改动任何检索行为之前，先跑一个只读诊断，得到每个问题的「关键证据在检索结果中的位置（rank）」分布，以及「检索分数序列是否存在可辨识的截断拐点」。据此判断：自适应收缩检索深度是否会在某类问题上丢掉关键证据、headroom 有多大。若诊断证明不存在安全收缩空间，则该方向在此数据集上判为不可行，不进入实现。

**Why this priority**: 历史三连证伪（024 去冗余 −0.91pp、025 语义聚合 −7.7pp、026 剪枝编译 −4.5pp）的共同机制是「缩减/改写 answer context 伤害了精确逐证据命中」。自适应深度同样会缩减 context，唯一能区别于既往失败的是「按需」而非「一刀切」。诊断是证明这个「按需」前提成立（或证伪它）的唯一手段，因此它必须先于任何实现，是本 feature 的生死前提。

**Independent Test**: 在固定的记忆库与问题集上，运行一个不调用作答/判题、只做检索的诊断，产出逐题报告：每个问题关键证据的 rank、当前预算是否已覆盖、以及分数序列的拐点结构。可独立验证，不依赖后续实现。

**Acceptance Scenarios**:

1. **Given** 一个已构建的记忆库与一组带标准答案证据的问题, **When** 维护者运行检索诊断, **Then** 报告对每个问题给出关键证据在检索结果中的 rank 与「是否在当前预算内」的判定。
2. **Given** 检索诊断已完成, **When** 维护者查看汇总, **Then** 报告给出「关键证据位于浅层（≤某 rank）的问题占比」与「分数序列存在可辨识拐点的问题占比」两个汇总指标。
3. **Given** 诊断显示「缩减深度会丢关键证据的问题占比过高」或「分数序列普遍无拐点」, **When** 维护者据此判定, **Then** 该方向判为不可行，不进入实现，且不改动任何检索路径。

---

### User Story 2 - 自适应检索深度：按问题自动决定证据量 (Priority: P1)

集成方希望每个问题只消耗「够用」的证据量：简单问题不拖入大量无关上下文，复杂问题保留足够证据链。系统按问题自动决定检索深度，替代当前「所有问题用同一固定深度」，平均证据消耗下降而答案质量不下降。

**Why this priority**: 这是本 feature 的核心价值——用「按需取量」替代「大力出奇迹」的固定大预算。它是「缩减 top-k」的正解，直接对齐「预算下提质」的产品哲学。优先级与 US1 并列，但实现必须排在 US1 诊断通过之后。

**Independent Test**: 在固定记忆库、问题集、作答模型、判题模型与聚合口径下，分别以「固定深度」与「自适应深度」跑完整评测，配对对比答案正确率与平均证据消耗。自适应机制默认关闭，关闭时行为与当前一致。

**Acceptance Scenarios**:

1. **Given** 自适应检索深度处于关闭状态, **When** 系统处理一个问答请求, **Then** 其检索与作答行为与当前固定深度完全一致（逐字节无变化）。
2. **Given** 自适应检索深度开启, **When** 系统处理一个简单问题（答案证据集中在少数结果）, **Then** 系统消耗的证据量显著低于固定深度，且答案仍正确。
3. **Given** 自适应检索深度开启, **When** 系统处理一个需要跨多个会话/来源证据的问题, **Then** 系统保留足够的证据量，不因自动收缩而丢失关键证据。
4. **Given** 自适应检索深度开启, **When** 系统以完整评测口径跑批, **Then** 平均证据消耗相比固定深度下降，且答案正确率不出现统计显著的下降（配对比较）。

---

### Edge Cases

- 某个问题的检索结果只有极少数（如 1 条）结果时，自适应深度如何表现？（应退化到原样，不因收缩把唯一证据丢掉。）
- 关键证据恰好位于自适应深度的截断边界附近时，如何保证不因噪声抖动而丢失？（需要保守下限。）
- 检索分数序列对某些问题没有明显的「相关→噪声」拐点时，自适应深度如何确定？（应回退到固定深度，而非强行收缩。）
- 三个检索信号（语义/关键词/实体）中的某一个不可用时，自适应深度是否仍能正确降级而不报错？（宪法 V。）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供默认关闭的自适应检索深度机制；关闭时检索与作答行为 MUST 与当前固定深度逐字节一致。
- **FR-002**: 自适应检索深度 MUST 按每个问题独立决定其证据量，不得对所有问题使用同一个固定值。
- **FR-003**: 自适应检索深度 MUST 保留 verbatim 原文片段的保底机制（chunk 保底），不得因自动收缩而把原文证据整体排除。
- **FR-004**: 当检索分数序列没有可辨识的截断拐点时，自适应深度 MUST 回退到固定深度，而非强行收缩。
- **FR-005**: 自适应深度 MUST 设保守下限，关键证据位于截断边界附近时不得因噪声抖动而丢失。
- **FR-006**: 诊断工具 MUST 对每个评测问题给出「关键证据在检索结果中的位置（rank）」与「是否在当前预算内」的逐题判定，以及「分数序列是否存在可辨识拐点」的判定与汇总指标。
- **FR-007**: 诊断与自适应机制 MUST 在检索信号缺失/失败时独立降级，不整体报错（宪法 V）。
- **FR-008**: 任何检索行为的改动 MUST 在合并前以「同记忆库、同问题集、同作答模型、同判题模型、同聚合口径」配对评测，证明答案质量不出现统计显著回退（宪法 IV）。

### Key Entities *(include if feature involves data)*

- **检索结果项**：一条被召回的证据，携带与查询的相关性得分、所属类别（原文片段 / 提取事实）、以及它是否覆盖了某问题的关键证据。
- **检索诊断记录**：针对单个问题的只读诊断快照，含关键证据在结果中的 rank、是否在预算内、以及分数序列拐点结构的标识。
- **自适应截断点**：针对单个问题、由检索分数序列推导出的证据量上限（可回退到固定值）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 诊断工具能对评测集中的 100% 问题给出「关键证据是否已进入预算」与「分数序列拐点结构」的明确判定，并给出可复现的汇总指标。
- **SC-002**: 自适应检索深度开启后（仅当诊断证明 headroom 存在），平均每个问题的证据消耗量相比当前固定深度**严格下降（幅度 > 0；具体阈值在诊断阶段按 headroom 数据冻结）**，且答案正确率相对当前基线无统计显著下降（配对比较）。
- **SC-003**: 关闭自适应机制时，系统在完整评测上的结果与当前基线完全一致（逐题无差异），证明新机制是纯 opt-in、无侵入。

## Assumptions

- 「证据消耗下降」的具体目标（初版曾设为 30%）不预先承诺：诊断阶段优先证明「缩减不丢关键证据」这一前提；若诊断证明任何缩减都会丢证据，则方向判为不可行，目标作废。正确率永远优先于省预算。
- 自适应深度是单一机制，可独立开关与评测；不涉及去冗余（去冗余方向已被 024/025/026 证伪，见 Clarifications）。
- 「不出现统计显著下降」沿用项目既有的配对显著性口径（同批、同 judge、多次作答多数票），具体阈值在 plan 阶段冻结。
- 本 feature 只作用于「检索之后、作答之前」的证据量决策，不触及写入侧（事实抽取、curation）——写入侧已在既往 feature 中反复证伪。
- 所有新机制默认关闭；转正（设为默认）是独立的后续决策，须满足宪法 IV 的评测回归门禁。
- 背景调研见 `docs/research/retrieval-budget-reduction-directions.md`（主分支工作树）与论文 TAA-k（arXiv 2606.11907）。注意：调研文档中并列的「AdaGReS 冗余去重」方向，经 024/025/026 历史 verdict 审计后，本 feature 不采用。
