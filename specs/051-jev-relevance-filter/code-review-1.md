## (a) Timing-sensitive tests in `filter/jev` — flake risk

**[MAJOR] Inverted timing margins in the shard-barrier test — the most probable source of the twice-flaked acceptance gate.**
`filter/jev/jev_test.go:150-190` (`TestFilterShardsConcurrentlyAboveThreshold`): the client is built with `Config{BaseURL, Model, APIKey, ShardSize: 48}` — `Deadline` is unset, so `New()` defaults it to **1s** (`jev.go` `New`, `cfg.Deadline = time.Second`), while the handler barrier guard is `time.After(2 * time.Second)`. Under cross-package parallel load (WSL2 acceptance runner), if the 4 shard handlers do not all arrive within 1s, `Filter` fails on the whole-call deadline (`jev.go` `Filter`, `context.WithTimeout(ctx, c.cfg.Deadline)`) and the test dies at `t.Fatalf("filter: %v", err)` — the informative 2s guard message never fires because the deadline (1s) trips first. The guard being *longer* than the client deadline inverts the intended failure attribution and turns scheduling jitter into test failure. Quantify: of the 3 wall-clock-sensitive tests here, this is the only inverted one; `TestFilterRespectsWholeCallDeadline` (200ms deadline vs `elapsed > time.Second` assertion = 5× margin) and `TestGateFailsOpenOnTimeout` (100ms vs 1s = 10× margin) are low-risk. `TestFilterNegativeCacheSkipsEndpointUntilTTL` correctly uses the swappable `c.now` (no sleeps) — good.
**Smallest fix**: in the barrier test set `Deadline: 30 * time.Second` in the `Config` and raise the handler guard to `30 * time.Second` (on true serialization the guard `t.Errorf` then fires with its intended message). Optionally assert shard concurrency post-hoc (arrival counter after `Filter` returns) instead of a live barrier. **Supervisor must confirm with**: `CGO_ENABLED=0 go test -count=5 -run 'TestFilterShardsConcurrently|TestFilterRespectsWholeCall|TestGateFailsOpen' ./filter/jev/` under load.

## (g) Eval harness integrity

**[BLOCKER] `jevArmRetrieve` timing defer is dead — `RetrievalMs` is always 0.**
`cmd/locomo-bench/jevfilter_arms.go:251-255`: `observation` is a plain local and every return is `return observation, nil` (unnamed results). Go sets the result values **before** deferred functions run; the deferred `observation.RetrievalMs = …` mutates the local after the copy and is lost. Consequence: `jevArmQuestionRow.RetrievalMs` is structurally 0 for every row → `jev_arms.jsonl` (a frozen measurement artifact) carries wrong `retrieval_ms`, and SC-007's "宽池检索" segment (`measureJevArmSegments` p50/p95) always reports 0 — dishonest segment accounting in the exact report the pre-merge gate must cite. No test catches it (`TestMeasureJevArmSegmentsSeparatesFilterSegment` hand-builds rows with `RetrievalMs: 10/20/30`; the `TestJevArmRetrieve*` tests never assert `RetrievalMs`). **Smallest fix**: use a named result (`func … (observation jevArmObservation, err error)`) or set `RetrievalMs` immediately before each return; add a test asserting `jevArmRetrieve(...).RetrievalMs > 0` is at least plumbed (or ≥0 and written).

**[MAJOR] `call_budget.retrieval_calls` is hard-coded 0 — the retrieval-budget exclusion audit is vacuous.**

Adjacent dead check: `jevValidityInput.B0ContinuityDeclared` is never set true in `writeJevArmArtifacts`, so the quickstart's "B0 receipts" requirement is never enforced. Smallest fix: count retrieval calls per question with explicit per-question semantics (or drop the field + the claim); wire `B0ContinuityDeclared` from the run config.

`jevfilter_protocol.go:1013` `attachJevFilterRegistration(protocol, registration)` mutates `protocol.Experiment.Filter`/`MechanismFlags` at **run** time — after `freezeEvalProtocol`/`freezeEvalProtocolFile` (`eval_protocol.go:315-335`, `eval_runner.go:1543`) computed `ProtocolHash`. **[MAJOR] Chunk-quota silently breaks the single-variable arm rule and SC-003/SC-005 comparability.**
`jevfilter_arms.go:jevArmRetrieve`: the pool snapshot and arm A/C go through `applyChunkQuota` (`chunks.go:219-239`, which can change pool **membership**, not just order) and `retrieveWithQuotaDiagnostics`' quota path (wide `max(6·topK,300)` then partition, `chunks.go:176-196`), while D/D-noRelax call `r.SearchFiltered` directly, whose internal wide search is the **raw** `Search(pool)` (no quota — `chunks.go:173-175` documents the skip). ## Verdict rationale

Engine + adapter are in good shape and the tests mostly assert real behavior; but the four-arm harness — which is this feature's pre-merge hard gate (Constitution IV) — ships with a structurally dead measurement (`RetrievalMs`), a vacuous audit field, a post-digest manifest mutation contradicting an AGENTS.md hard rule and its own comments, a cross-recipe comparability hole under chunk quota, and a partial-run verdict that can read "GO". Evidence produced by a broken meter cannot gate a merge, and T19 must not run until these are fixed (a rerun after fixes would also discard paid eval spend). Unblock list: fix the BLOCKER + the five MAJORs (all small, localized edits), harden the shard-barrier test margins, then run the T19 four-arm gate.
