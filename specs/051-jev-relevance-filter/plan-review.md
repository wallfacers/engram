## Review — plan 051-jev-relevance-filter (cross-vendor, plan-stage)

I reviewed `spec.md`, `plan.md`, `research.md`, `data-model.md`, `quickstart.md`, all three `contracts/*`, plus the named seams: `memory/retriever.go`, `memory/entrystore.go`, `mcpserver/tools.go`, `mcpserver/parity_test.go`, `cmd/locomo-bench/{main.go,eval_runner.go,paired_eval.go,stats.go}`, `specs/038-.../contracts/evaluation-protocol.md`, `docs/evaluation/results.md`, `docs/engram-probe-curation-design.md`, `AGENTS.md`/`CLAUDE.md`. Review-only: no files edited, no commands run.

### Correct

- Parity invariant is correctly scoped to **responses**, not schema: `memorySearchOutput` (`mcpserver/tools.go:41-46`) can carry new `omitempty` fields without touching the locked behaviour, and the existing parity check (`mcpserver/parity_test.go:10-60`, `memory_search` == direct `Retriever.Search`) is the right place to extend it.
- Interface shape is consistent with the repo's optional-sidecar pattern (`embedding.NewReranker` typed-nil discipline, `AGENTS.md:80`), and `filter/` avoids the import cycle (`memory` → `filter` only) — matches `memory/semantic_cluster.go:115-121` precedent.
- No schema change is genuinely sufficient for read-side telemetry; `R5` correctly refuses `usagelog` writes.
- Opt-in/default-off, fail-open, structural-facts-only degradation, "no partial shard adoption", and "LoCoMo-only" wording all match Constitution I/V and the `AGENTS.md:79` degradation rule.
- Complexity Tracking legitimately records the death-rule amendment with its rationale and the honest non-restatement of the 91.43% attribution (matches spec FR-006/FR-007 and design §19).
- Single-mechanism treatment discipline is respected in spirit (one new mechanism, one feature).

### Findings

- **[BLOCKER] The clarified "A+B 双落地" B-path (adapter/skill-side local filtering) is silently dropped — spec/plan contradiction.** `spec.md` FR-001: "同时 MUST 提供适配器/skill 侧过滤路径（宽池检索后本地过滤，不依赖新 MCP 参数），两条路径共享同一过滤语义与遥测"; clarify Session 2026-09-23 Q1 repeats it. `plan.md` Complexity Tracking row 3 instead *rejects* that path ("skill 侧自行拼装被否：路径不统一、parity 无法证明"), and `plan.md` Project Structure ships no B-path deliverable (only `skills/engram/SKILL.md` knobs). Fix: either add the B-path deliverable or formally amend FR-001/Q1 with the maintainer decision recorded in `spec.md` + the plan; the "knobs" line does not cover it.

- **[BLOCKER] The write gate's secret-classification boundary is undefined and conflicts with a hard rule.** The gate must send the raw user turn/draft to a third-party cloud endpoint (`plan.md` R6: `Gate(ctx, userTurn, draft)`) precisely when the draft may contain a secret (`contracts/write-gate.md` "is_secret" row). The contract enumerates only "logs / tool responses / tracked files" as forbidden destinations; `AGENTS.md:81` Secrets and Constitution I are about keys leaving the process. Additionally, the given authorisation is scoped to "this Jev filter surface only" (objective 3), while `FR-010`/US4 ship a second cloud path. Fix: state the transmission boundary explicitly, require local secret-shape pre-detection that short-circuits the cloud call (or keep `is_secret` local-only), and make the AGENTS.md amendment name the write path or split the write gate into its own increment.

- **[MAJOR] SC-004 ("empty-injection rate on gold-absent questions") is unmeasurable under the stated protocol.** Gold-absent questions are LoCoMo category 5, which the harness **skips by default** (`cmd/locomo-bench/main.go:351` `-adversarial 0`), is **excluded from the 1540 denominator** (`cmd/locomo-bench/stats.go:220-221`; `dataset.go:210`), and the 1540 set is exactly the answerable set (446 adversarial / 1540 answerable, `abstain_test.go:262-273`). `specs/038-.../evaluation-protocol.md` cohort 3 requires "category-5 adversarial when reporting false-answer behavior". Fix: add a declared category-5 block (refusal-scoring convention, `main.go:2424-2428`) to the arm table for C and D, define "empty injection" operationally, and state the population.

- **[MAJOR] The eval does not satisfy the repo's own formal protocol machinery.** `specs/038-.../evaluation-protocol.md` freezes axes (incl. **context parity = equal SHA-256 of the actual provider-facing answer-user bytes**), requires per-row provider-call audit + per-repeat validation receipts before any accuracy is shown, and pilot/warm-up/3-rep-in-one-window sequencing; `cmd/locomo-bench/eval_runner.go:341,343-363` registers additive mechanism flags in the mechanism-binding manifest, and `main.go:306-311` marks mechanism flags "formal context required". Arm D deliberately changes the provider-facing bytes, so the "sole intended variable" must be re-declared and the 038 gate re-scoped per contrast (A↔B changes budget, B↔D changes the filter). None of this appears in the plan. Fix: name the four frozen manifests, the new mechanism key, the declared intended variable, the validity artifacts, and how the context-parity gate is replaced.

- **[MAJOR] The acceptance gate has no significance/pairing discipline.** SC-001 is a bare `D ≥ B − 0.5pp`; the governing protocol gate is "delta >= −0.5pp **and no statistically significant regression**", and the repo's own noise record is a documented single-run drift of ≈8.6pp (`docs/evaluation/results.md:102`, `reports/043-*:64`) with "跨 run 对比必须 run 内配对". Existing exact-McNemar tooling is available and unused by the plan (`cmd/locomo-bench/paired_eval.go:29-59,61-64`). Fix: require within-run pairing, report exact-McNemar p + paired CI for B↔D (and A↔C for the degraded claim), and state whether the outcome feeds `promotionVerdictFor` (`paired_eval.go:210-221`).

- **[MAJOR] θ/pool tuning on the gate set is not pre-registered (in-sample-tuning risk).** `research.md` R3 allows `ENGRAM_JEV_THETA/RELAX_THETA/KSHOW_MAX` overrides "（评测/校准用）", quickstart §5/§6 repeat this, and spec Assumptions say θ "需用自有标注校准" — but the only conversation corpus is LoCoMo, i.e. the gate set. The repo already disqualified a feature for exactly this (`docs/evaluation/results.md:116`). Fix: freeze θ/pool/shard size before the gated run, record them in the manifest, and declare any θ sweep diagnostic-only (never the reported gate result), with calibration on a pre-registered disjoint split if a sweep is needed.

- **[MAJOR] SC-005 (degraded ≥ A) has no arm, and the degrade contract is ambiguous.** The contract says degraded = "RRF 前 `limit` 条" of the wide pool, i.e. identical to arm C's shown set — but the plan never states that identity, and `SearchFiltered`'s signature has no `limit` parameter while the same contract says "`flt == nil` 时等价 `Search(ctx, query, min(pool, limit))`" and "N 由调用方 limit 决定" (`contracts/relevance-filter.md` §4). Fix: define the truncation owner (caller vs composition), define `SearchFiltered` error semantics (filter errors must not propagate; only the underlying `Search` errors do), and declare arm C as the degraded proxy or add a degraded arm.

- **[MAJOR] SC-003 compares recall@shown at unequal budgets.** D may show up to `KShowMax=12` while C shows 8, so `recall@shown(D) ≥ recall@shown(C)` is partly a budget artifact rather than evidence that conditionalised filtering beats blind truncation. Fix: equalise the shown budget for the gate (e.g. C truncated to 12, or D restricted to its top-8), and name the existing per-hit evidence-recall seam (`evidenceRecallAt` in `cmd/locomo-bench/multiquery.go:441`) as the metric source.

- **[MAJOR] The two-stage relaxation without the design's guard undermines the headline "honest empty" objective and makes SC-004 near-vacuous.** Design §21.2 conditions relaxation on `needs_memory=true`; `research.md` R3/spec clarify Q5 remove any guard, so any query with a single `p ≥ 0.35` injects up to 3 entries — while SC-004 rewards emptiness on gold-absent questions, and C (pure truncation) is a comparator that is essentially never empty. Fix: make relaxation opt-in/gated, and either strengthen the metric (D injects **no** non-gold entries on gold-absent questions) or report both variants.

- **[MAJOR] Pinned bypass has no data path and its cap is undefined — the edge case the spec asked the plan to nail is left open.** `memory.Result` has no `Pinned` field (`memory/retriever.go:110-121`); only `memory.Entry` has it (`memory/entrystore.go:19-24`), and the Entry is already in hand when results are built (`memory/retriever.go:307-320`), so the cheapest fix is one extra field. There is also **no existing retrieval convention** for "trigger 命中即注入" (`Pinned` is used only in write/curation/budget paths). And `contracts/relevance-filter.md` §5 injects pinned entries "排最前，不计 Dropped" without saying whether they count against `KShowMax` — which directly threatens SC-002's "≤12 shown". `spec.md` Edge Cases literally says this "需在 plan 定死". Fix: add `Pinned` to `Result` (no MCP output change), define trigger-match semantics (case/substring/token), and define `total ≤ KShowMax + pinned` or `KShowMax` inclusive.

- **[MAJOR] FR-005 telemetry contradicts the frozen MCP output.** FR-005 requires backend/θ/kept/dropped/**latency**/**cost**/degraded in the tool's `filter` field; `contracts/memory-search.md` and `data-model.md` output only `{backend,theta,kept,dropped,degraded}`. Either include `latency_ms`/`cost_usd` (SC-007 per-segment accounting depends on them) or amend FR-005 and state that the harness instruments them itself.

- **[MAJOR] Per-turn latency budget is unbounded on a "per-turn affordable" path.** The contract allows 10s per Jev request (`contracts/relevance-filter.md` §5) and the plan claims "degraded 路径零附加延迟" — true only when unconfigured. With a configured-but-hanging endpoint every search pays up to 10s, and "单次失败不熔断" (`research.md` R4) makes that tax permanent with no negative cache; the write gate adds the same to every `memory_write`, against the "write-in-turn + notify-in-turn" contract (spec FR-010). Fix: define a per-search filter deadline (ctx-derived, ~1s), a short-TTL failure cache, and a write-gate timeout with fail-open on deadline.

- **[MAJOR] Harness insertion point and "shown" measurement are unnamed.** Arm D must be inserted into the answer path that today goes through `retrieveWithQuotaDiagnostics`/`retrieveWithDiagnostics` → chunk selector/quota → compiler/packer (`cmd/locomo-bench/multiquery.go:95-122,171-182`), and there is no separate "retrieve K, show M" knob today (`main.go:324` single `--top-k`). Without naming the seam and the measurement point, "D avg shown ≤12" and "answer-context token ≤ B/3" are not well-defined (a packer/quota can change the injected count independently of the filter).

- **[MAJOR] Amending only `AGENTS.md` leaves a contradictory death rule in `CLAUDE.md`.** The identical clause is at `AGENTS.md:82` and `CLAUDE.md:82` (no sync script in `scripts/`). Fix: amend both, or state that `CLAUDE.md` is derived and update it in the same commit.

- **[MINOR] Scale constant inconsistency + unvalidated inputs.** Technical Context says `candidate_pool ≤ 150` while `contracts/memory-search.md` allows ≤500; the gated pool (64/100/150) is not pre-registered. Unspecified: `candidate_pool < limit`, `theta` out of (0,1), `θ < RelaxTheta` (inverts the two-stage logic), `filter="jev"` with `pool == limit`. Add explicit clamps/validation and a test per rule.

- **[MINOR] Knob ownership is ambiguous.** `ENGRAM_SEARCH_POOL` / `ENGRAM_FILTER` are listed under `skills/engram/SKILL.md`, but a skill file cannot set the server's env; if `mcpserver/config.go` reads them as defaults, the parity invariant must be stated as "when unset" and the clients' inability to set server env documented.

- **[MINOR] Reproducibility of the model identity.** Wire examples pin the floating tag `"jev-latest"`; eval/publication requires a concrete revision recorded in the run manifest (038 "frozen axes", no secrets).

- **[MINOR] Output ordering vs `score`.** Select reorders by Jev probability while `score` stays RRF (`contracts/relevance-filter.md` §3/§5), producing non-monotonic scores for consumers; state it explicitly and decide whether the skill may re-sort.

- **[NIT] Test coverage additions worth pre-declaring:** an offline test asserting `filter="jev"` with no keys performs **no** network attempt and returns exactly RRF top-`limit` with `degraded=true`; a "no retry" policy statement so the degraded arm is deterministic for SC-005; explicit statement that only manual `memory_write` is gated (not `memory_ingest`/extraction/curation); a cost/budget estimate + `--estimate` step for 4 arms × 3 reps × 1540 before spending on the box (`docs/evaluation/results.md:76` DEATH-RULE-adjacent cost discipline, AutoDL "空闲必停"); and committing the normative design doc — `docs/engram-probe-curation-design.md` (the source of §19-25, §18.1/§22 question texts and §25's "write gate **after** the score gate" sequencing that this plan supersedes) is currently **untracked**.

VERDICT: block

Blocking items: the dropped clarified B-path (FR-001), the write-gate secret-transmission boundary, and the eval protocol's inability to produce SC-004/SC-005 and a protocol-valid SC-001 as written. All are plan-stage fixes; nothing reviewed here is an implementation defect.
