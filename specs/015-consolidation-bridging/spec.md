# Feature Specification: 离线固结 · 跨 session 桥接合成

**Feature Branch**: `015-consolidation-bridging`

**Created**: 2026-07-25

**Status**: Draft

**Input**: 设计文档 [docs/superpowers/specs/2026-07-25-offline-consolidation-bridging-design.md](../../docs/superpowers/specs/2026-07-25-offline-consolidation-bridging-design.md)（唯一事实来源，本 spec 不引入新决策）

## 背景与问题

记忆引擎当前只有两个写入阶段：在线抽取（把对话轮次变成原子事实）与策展（删除、
合并、抑制近重复）。两者都是**逐 session** 处理的，因此散落在不同 session 的证据
之间的连接从未被显式记录下来。

后果是：需要串联两条不同 session 的事实才能回答的问题（多跳问题），其证据虽然都
在库里，却各自埋在检索结果的深处，谁也进不了送给回答方的上下文。既有诊断已确认
这是当前唯一尚未解决的结构性召回瓶颈，且已三次证伪「改写已有记忆的表示」这条路
——因为改写会对称地抬高所有记忆的可检索性，不改变目标证据的**相对**位置。

本特性引入第三个写入阶段：一趟离线的后台整理，跨 session 找出彼此相关的证据对，
并**合成一条新的、内容全新的记忆**来显式记录它们之间的连接。这条新记忆本身是可
被直接检索到的，因此把「需要多跳才能拼出的答案」变成「一跳就能命中的事实」。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 先证伪：在投入建设前免费判定该方案是否可行 (Priority: P1)

维护者在写任何引擎代码之前，先用已有的历史评测产物跑两级免费诊断，得到一个明确
的「值得建 / 不值得建」判决。第一级完全不调用任何模型；第二级只需要向量化能力，
不需要回答模型。任一级不达标，方案当场作废，不浪费任何建设成本。

**Why this priority**: 这是唯一能在零建设成本下否决整个方案的机会。历史上有过
「先建后验」而浪费的先例。它本身即可独立交付价值——哪怕结论是「判死」，也是一个
有价值的、可归档的判决。

**Independent Test**: 只用历史评测产物与现有的「仅检索、不调用回答模型」评测模式
即可完整执行，不依赖本特性的任何新代码，产出一份含四项判据实测值的判决报告。

**Acceptance Scenarios**:

1. **Given** 已有历史评测产物（含每道题的标准证据标注与检索结果），**When** 执行
   第一级诊断，**Then** 系统产出「候选召回率」与「候选规模」两项实测值，并对照
   预设阈值给出通过/灰区/判死结论，全程零模型调用。
2. **Given** 第一级诊断通过，**When** 执行第二级诊断（把标准证据对按模板拼成理想
   桥接记忆插入库的副本后重新检索），**Then** 系统产出「理想桥接的可发现性」与
   「覆盖增益」两项实测值并给出结论，全程不调用回答模型。
3. **Given** 任一级诊断判死，**When** 维护者查看判决报告，**Then** 报告明确指出
   是哪一项判据未达标及其实测值，且流程终止、不进入建设阶段。
4. **Given** 第一级诊断结果落在灰区，**When** 维护者调整一次候选筛选参数并重测，
   **Then** 若仍在灰区则按判死处理，不允许第二次调整。

### User Story 2 - 桥接合成：显式驱动一趟固结，产出可检索的桥接记忆 (Priority: P2)

维护者对一个已经装载完记忆的库显式触发一趟固结。系统跨 session 找出相关的证据
对，逐对询问语言模型是否存在一条可推出的、非冗余的连接事实；对确实存在的，写入
一条新的记忆；对不存在的，跳过。整个过程只增不改：原有记忆一条都不会被修改或
删除。

**Why this priority**: 这是本特性的核心能力，也是评测验证的前提。它必须能被显式
驱动（而非只能等后台定时触发），否则无法在评测中复现。

**Independent Test**: 在一个装载了跨 session 记忆的库上显式触发一趟固结，检查新
记忆已产生、原有记忆逐条未变、且新记忆能被正常检索到。

**Acceptance Scenarios**:

1. **Given** 一个含多个 session 记忆的库，**When** 显式触发一趟固结，**Then**
   系统产出若干条新的桥接记忆，且每条都记录了它由哪两条源记忆合成。
2. **Given** 一趟固结已完成，**When** 检查原有记忆，**Then** 每一条源记忆的内容
   与总条数**逐条完全未变**。
3. **Given** 一条新产生的桥接记忆，**When** 用常规方式检索，**Then** 它与其他
   记忆一样可被命中，无需任何特殊查询方式。
4. **Given** 语言模型对某个证据对判定「不存在可推出的连接」，**When** 该对被处理，
   **Then** 系统不产生任何新记忆，也不留下任何残留。
5. **Given** 语言模型返回的结果引用了库中不存在的源记忆，**When** 系统校验该结果，
   **Then** 拒绝写入，并按告警处理而非中断整趟固结。
6. **Given** 同一个库，**When** 连续触发两趟固结，**Then** 第二趟不产生任何重复的
   桥接记忆，桥接记录总数不变。
7. **Given** 库中已存在桥接记忆，**When** 再次触发固结，**Then** 已有的桥接记忆
   不会被当作证据对的候选（不产生「桥接之上的桥接」）。
8. **Given** 未配置语言模型，**When** 触发固结，**Then** 系统完全不执行任何操作，
   不产生任何副作用，也不报错。

### User Story 3 - 后台自动固结：随记忆增长自动维护，且多实例安全 (Priority: P3)

固结随记忆增长在后台自动进行，无需人工触发。当同一个库被多个进程同时服务时，
任一时刻只有一个进程在执行固结，不会重复劳动或互相干扰。一趟固结被中断后，
下次运行能从中断处继续，已完成的部分不重做。

**Why this priority**: 这是产品化与未来多租户服务化所必需的作业形态，但对评测
验证不是必需的——US2 的显式驱动已足以验证效果。因此排在核心能力之后。

**Independent Test**: 启动两个后台工作器指向同一个库，验证只有一个真正执行；
中断一趟固结后重启，验证已完成的部分不重复处理。

**Acceptance Scenarios**:

1. **Given** 两个工作器指向同一个库，**When** 两者同时尝试执行固结，**Then** 只有
   一个真正执行，另一个安静让出。
2. **Given** 一趟固结执行到一半被中断，**When** 下次运行，**Then** 已完成的证据对
   不重复处理，只补做未完成的部分。
3. **Given** 一趟固结正在进行，**When** 单趟处理量达到预设上限，**Then** 本趟停止
   并留待下趟继续，不会无限制消耗资源。
4. **Given** 固结过程中发生任何失败，**When** 失败被捕获，**Then** 记录告警并安全
   跳过，既有的检索与写入能力完全不受影响。

---

### Edge Cases

- **没有任何跨 session 证据对**（例如库中只有一个 session）：固结正常结束，产出
  零条桥接记忆，不报错。
- **某条源记忆在固结过程中被并发删除**：该证据对被跳过，不产生悬空血缘记录。
- **语言模型调用失败或超时**：该证据对跳过并告警，整趟固结继续，不中断。
- **语言模型返回的连接事实与源记忆内容重复**（非新增信息）：视为无效，不写入。
- **同一对源记忆以不同顺序被枚举到**：视为同一对，只合成一次。
- **候选证据对数量超出单趟上限**：按得分高低取前列，其余留待下趟。
- **库中记忆量极小**（不足以形成任何候选对）：固结不执行，不产生告警噪声。

## Requirements *(mandatory)*

### Functional Requirements

#### 证伪门（US1）

- **FR-001**: 系统 MUST 提供一级完全零模型调用的诊断，输出「候选召回率」与
  「候选规模」两项实测值。
- **FR-002**: 候选召回率的分母 MUST 为「多跳失败题中至少存在一个跨 session 标准
  证据对」的题数；分子 MUST 为「其中至少有一个此类证据对出现在候选集里」的题数。
- **FR-003**: 系统 MUST 对照预设阈值判定：候选召回率 ≥ 60% 为通过、< 40% 为判死、
  40–60% 为灰区；候选规模 ≤ 2 万为通过、> 5 万为判死。
- **FR-004**: 灰区 MUST 只允许调整一次筛选参数后重测；重测仍在灰区 MUST 按判死
  处理。
- **FR-005**: 系统 MUST 提供二级诊断，把标准证据对按固定模板（不调用语言模型）
  拼成理想桥接记忆插入库副本后重新检索，输出「理想桥接可发现性」与「覆盖增益」。
- **FR-006**: 二级诊断 MUST 不调用任何回答模型，只依赖向量化与既有的仅检索评测
  模式。
- **FR-007**: 系统 MUST 对照预设阈值判定：理想桥接可发现性 ≥ 50% 为通过；覆盖增益
  MUST 严格大于 0 才算通过，且 MUST 沿用既有历史杠杆所用的同一覆盖度量口径。
- **FR-008**: 任一判据判死时，系统 MUST 终止流程并明确指出未达标的判据及其实测值。

#### 桥接合成（US2）

- **FR-009**: 系统 MUST 只在源记忆分属**不同 session** 时才将其纳入候选证据对。
- **FR-010**: 系统 MUST 只在两条源记忆**共享至少一个实体**时才将其纳入候选。
- **FR-011**: 系统 MUST 按共享实体的稀有程度给候选对打分，并只保留每个库中得分
  最高的前 K 对（K 的初始值为 2000）。
- **FR-012**: 候选枚举 MUST 完全确定性、零模型调用；同分时 MUST 有稳定的排序规则，
  使同一输入永远产出同一候选序列。
- **FR-013**: 系统 MUST 允许语言模型对任一候选对回答「不存在可推出的连接」，并在
  收到此回答时不产生任何记忆。
- **FR-014**: 系统 MUST 校验语言模型返回结果所引用的源记忆确实存在；引用不存在的
  源 MUST 拒绝写入并告警。
- **FR-015**: 系统 MUST NOT 修改或删除任何源记忆（只增不改）。
- **FR-016**: 合成的桥接记忆 MUST 与普通记忆同构，可被既有的常规检索方式直接命中，
  **不得要求任何检索侧改动**。
- **FR-017**: 系统 MUST 为每条桥接记忆持久化其血缘（由哪两条源记忆合成、何时合成），
  且该血缘 MUST 支持整批查询与整批删除。
- **FR-018**: 系统 MUST NOT 把已有的桥接记忆纳入候选证据对（禁止二阶固结）。
- **FR-019**: 系统 MUST 保证幂等：对同一对源记忆重复运行不产生第二条桥接记忆。
- **FR-020**: 未配置语言模型时，系统 MUST 完全不执行固结，且不产生任何副作用或
  错误。

#### 后台作业（US3）

- **FR-021**: 固结 MUST 可被显式驱动（供评测复现），也 MUST 可随记忆增长在后台
  自动触发。
- **FR-022**: 同一个库被多个进程服务时，任一时刻 MUST 只有一个进程执行固结。
- **FR-023**: 系统 MUST 对单趟处理的候选对数量设硬上限，且该上限 MUST 可配置。
- **FR-024**: 一趟固结中断后重跑 MUST 只补做未完成的部分。
- **FR-025**: 固结过程中的任何失败 MUST 被安全捕获（告警并跳过），MUST NOT 影响
  既有的检索与写入能力。

### Key Entities

- **桥接记忆（Bridge Memory）**：一条由两条跨 session 源记忆合成的新记忆，内容是
  它们之间可推出的连接事实。与普通记忆完全同构，可被常规检索命中。
- **候选证据对（Candidate Pair）**：两条来自不同 session、共享至少一个实体的源
  记忆的组合，带一个基于共享实体稀有度的得分。
- **桥接血缘（Bridge Provenance）**：记录一条桥接记忆由哪两条源记忆合成、何时
  合成。用于审计、整批回滚，以及未来按租户统计与开关。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一级诊断在**零模型调用**下完成，产出候选召回率与候选规模两项实测值
  并给出明确判决。
- **SC-002**: 二级诊断在**不调用回答模型**的前提下完成，产出理想桥接可发现性与
  覆盖增益两项实测值并给出明确判决。
- **SC-003**: 两级诊断的每项判据都有事先写定的通过/判死阈值，判决结论与阈值的
  对照可被第三方独立复核。
- **SC-004**: 固结完成后，**100%** 的源记忆内容与条数逐条未变。
- **SC-005**: 连续两趟固结后，桥接记忆总数与第一趟后**完全相同**（零重复）。
- **SC-006**: 未配置语言模型时，系统行为与未启用本特性时**完全一致**（无新增记忆、
  无错误、无血缘记录产生）。
- **SC-007**: 两个进程同时服务同一个库时，实际执行固结的进程数**恒为 1**。
- **SC-008**: 语言模型返回「无连接」或引用了不存在的源时，产生的记忆数为 **0**。
- **SC-009**: 全量评测中，多跳问题的正确率相对当前基线**提升**，且整体正确率
  **不低于**当前基线（回归门）。

## Assumptions

- 本特性的「用户」是记忆引擎的维护者与集成方，不涉及终端用户界面。
- 证伪门所需的历史评测产物（含标准证据标注、检索结果、已装载的库）可从既有的
  归档中取回；本地缓存丢失不影响可执行性。
- 「多跳失败题」沿用既有诊断的同一口径（同一基线运行的三次重复中多数判错的多跳
  题），以保证与历史结论可比。
- 覆盖增益的度量口径沿用既有历史杠杆所用的同一把尺，不另立标准，否则本次结论
  与历史结论不可比。
- 语言模型与向量化能力均为可替换、可离线部署的外部组件；两者缺失时系统按降级
  处理而非报错。
- 未来的多租户服务化只要求本次在数据模型与作业形态上不堵死（血缘可整批查删、
  幂等可恢复、有预算上限、多实例安全），**不要求本次交付任何多租户实现**。
- 抽象合成、去重合并、二阶固结均明确不在本次范围内。
