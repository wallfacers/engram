# Feature Specification: 企业级文档信息架构

**Feature Branch**: `019-docs-information-architecture`

**Created**: 2026-07-28

**Status**: Draft

**Input**: User description: "重新整理 docs 下的文档，合并重复内容，明确探索方向，形成方便 AI 检索和用户查看的企业级文档规范；已确认的设计见 `docs/archive/designs/2026-07-28-documentation-information-architecture-design.md`。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 获取唯一可信的当前答案 (Priority: P1)

作为 engram 的使用者、维护者或 AI agent，我需要针对“当前支持什么、当前评测结果是多少、
某项实验是否出货”等问题找到唯一的现行正本，并能立即识别文档是否描述已交付能力、
未实现提案或历史记录，从而避免依据过期内容做出错误判断。

**Why this priority**: 当前最严重的问题不是缺少信息，而是多个文档同时维护相同结论且状态
互相冲突。若无法先确定唯一正本，目录调整和内容美化都不能提升可信度。

**Independent Test**: 使用预先登记的典型问题集查询文档，验证每个问题都指向一个明确的
现行正本，且答案不会把提案或归档内容解释为当前能力。

**Acceptance Scenarios**:

1. **Given** 使用者查询当前 LoCoMo 或 LongMemEval-S 结果，**When** 从文档入口查找，
   **Then** 只得到一份当前结果正本，且 LongMemEval-S 明确为全量 500 题。
2. **Given** AI agent 查询 CLI、curation 或记忆新鲜度能力，**When** 阅读当前能力文档，
   **Then** CLI 和 opt-in curation 被识别为已交付，而完整新鲜度能力被识别为尚未实现。
3. **Given** 一项实验已经收口为 NO-GO，**When** 使用者查询其最终状态，**Then** 默认
   入口先给出最终裁决，再按需链接到历史证据，而不会把旧计划当作下一步。

---

### User Story 2 - 按任务快速浏览文档 (Priority: P2)

作为第一次接触 engram 的用户，我需要按“如何接入、如何运行评测、如何理解架构、如何
查看路线”等任务进入文档，而不必先理解仓库的 feature 编号、实验时间线或文件命名历史。

**Why this priority**: 企业级文档必须以读者任务组织，而不是以作者写作时间组织。清晰导航
能让高质量内容真正可用，也降低维护者反复解释入口的成本。

**Independent Test**: 让不了解历史目录的读者从文档门户完成接入指南、架构说明、评测
运行手册、当前结果、产品方向和历史证据六类查找，验证每类内容在两次导航动作内到达。

**Acceptance Scenarios**:

1. **Given** 新用户需要接入 MCP 或 CLI，**When** 从文档门户选择使用指南，
   **Then** 可直接到达对应的现行操作文档。
2. **Given** 维护者需要复现评测，**When** 选择评测运维入口，**Then** 可区分评测配方
   与远端机器生命周期，并找到各自正本。
3. **Given** 读者只关心当前产品方向，**When** 选择产品与路线入口，**Then** 不需要
   穿过历史实验台账或已失效的竞品差距推断。

---

### User Story 3 - 审计历史结论与证据 (Priority: P3)

作为维护者或研究者，我需要在不污染当前状态回答的前提下，追溯负结果、旧决策、
诊断方法和正式 feature 证据，从而理解一个方向为何被采用、拒绝或停止。

**Why this priority**: engram 的负结果和门控过程具有研究与工程价值，不能因整理而丢失；
但它们也不能继续与现行能力平铺在同一入口。

**Independent Test**: 从任一实验最终裁决出发，验证能够追溯到完整历史报告或正式 feature
证据，同时历史文档首屏明确说明其状态、最终 outcome 和现行替代入口。

**Acceptance Scenarios**:

1. **Given** 使用者从实验裁决表查看 temporal T-4，**When** 请求详细证据，
   **Then** 可到达完整诊断，并明确看到该方向的最终 NO-GO 状态。
2. **Given** 历史设计已被正式 feature 承接，**When** 维护者查看该设计，
   **Then** 能识别对应 feature 和最终 outcome，而不会看到未加说明的“待实现”状态。
3. **Given** 历史材料完全被正式规格覆盖且没有独有证据，**When** 完成迁移，
   **Then** 冗余材料可以删除，正式规格仍足以解释需求与契约。

---

### User Story 4 - 持续维护而不重新漂移 (Priority: P4)

作为文档维护者，我需要统一的生命周期、权威边界、复核信息和归档规则，使新增或更新
文档时能够判断内容应放在哪里、哪些事实只能引用而不能复制。

**Why this priority**: 一次性清理只能解决当前混乱；没有治理规则，快速变化的评测结果和
feature 状态会再次散落到多个文件。

**Independent Test**: 维护者依据文档规范，对一个新的当前结果、一个未实现提案和一个
已收口实验分别选择归属与状态，验证不同维护者得到一致分类。

**Acceptance Scenarios**:

1. **Given** 新评测结果产生，**When** 维护者更新文档，**Then** 完整结果只进入结果正本，
   其他现行文档只引用该正本。
2. **Given** 新探索尚未实现，**When** 创建或更新相关文档，**Then** 文档明确表明其提案
   状态，且当前能力清单不把它列为已交付。
3. **Given** 一个方向已经收口，**When** 维护者归档完整过程，**Then** 仍有效结论先进入
   现行正本，历史全文随后冻结并退出默认导航。

### Edge Cases

- 同一主题同时存在当前正本、历史报告和旧路径入口时，默认查询必须只选择当前正本，
  旧入口只能引导而不能复制结论。
- 历史报告中的数字与当前结果不同且均真实时，两者必须按适用时间和评测口径隔离，
  不能静默覆盖或直接横比。
- 一份旧文档同时包含仍有效规则和过时计划时，必须先拆出有效规则，再归档原始全文。
- 一个已实现但默认关闭的能力不能被简化为“已交付默认能力”或“未实现”。
- feature 的任务复选框未更新但最终 verdict 已明确时，不能从复选框推断 feature 状态。
- 历史设计只以行内路径被引用时，迁移后引用仍需可导航并指向正确目标。
- 文档中存在个人姓名、口语化原始反馈或其他非必要敏感上下文时，现行问题定义必须保留
  需求含义而移除原始对话。
- 不同章节使用相同标题导致深链依赖顺序时，整理后标题必须具有稳定、唯一的语义。
- 并行工作在整理期间修改目标文档时，该文档不得被静默覆盖或丢弃。

## Requirements *(mandatory)*

### Scope Boundaries

- 内容编辑范围是 `docs/`。
- 新 feature 的规格产物属于流程记录，不计入产品文档重组范围。
- 既有正式 feature 材料只允许修改指向历史设计稿的链接目标，不允许改变需求、契约、
  任务状态或 verdict。
- 仓库顶层介绍、许可、维护者指引、宪法、产品代码、测试、数据迁移和配置均为只读。
- 验收时对仓库内全部 tracked 文档执行只读链接检查；“全仓检查”不代表扩大编辑范围。

### Functional Requirements

- **FR-001**: 文档集合 MUST 提供一个面向用户与 AI agent 的统一门户，并按使用任务而非
  写作时间组织现行内容。
- **FR-002**: 门户 MUST 覆盖使用指南、架构、评测运维、当前结果、产品能力、路线与探索、
  研究方向和历史证据。
- **FR-003**: 每份现行文档 MUST 只承担一个明确的主要职责，并在主标题之后、第一个二级
  章节之前说明其摘要和权威边界。
- **FR-004**: 每个高频查询领域 MUST 只有一个现行正本；至少包括当前能力、当前评测结果、
  实验最终裁决、CLI、MCP、记忆架构、评测运行方法、产品路线和论文方向。
- **FR-005**: 每份现行、提案、归档和迁移文档 MUST 提供非空标题、摘要、生命周期、
  至少一类目标读者、维护责任、人工复核日期和至少一个权威查询主题；归档文档还 MUST
  提供最终 outcome 或现行替代入口，迁移文档还 MUST 提供唯一新正本。
- **FR-006**: 文档生命周期 MUST 且只能使用五种语义：稳定现行、变化中的现行、未实现
  提案、历史归档、旧路径迁移；不得用同一个“活跃”标签混合这些含义。
- **FR-007**: 功能和实验状态 MUST 与文档生命周期分离，并使用互斥语义：默认出货；
  受支持但必须显式启用的出货能力；仅为评测或诊断保留、默认关闭且不受产品承诺的实验
  能力；计划中；NO-GO；实现前取消。
- **FR-008**: 当前状态查询 MUST 默认排除归档和迁移文档；提案文档不得作为已交付能力的
  证据。
- **FR-009**: 当前评测结果 MUST 有唯一总表，所有数字均说明数据集、答题模型、判题模型
  和评测配方。
- **FR-010**: LongMemEval-S 当前结果 MUST 以全量 500 题为准；100 题先导实验只能作为
  明确标记的历史证据。
- **FR-011**: 实验最终裁决 MUST 有统一索引，能从短结论追溯到正式规格、评测日志或
  完整历史报告。
- **FR-012**: 当前能力说明 MUST 与已交付的 CLI、显式启用的 curation 和当前存储能力
  一致，并明确哪些能力并非默认路径。
- **FR-013**: 完整记忆新鲜度、状态一致性和按需召回 MUST 明确标记为尚未实现的问题，
  不得被当前能力说明暗示为已解决。
- **FR-014**: 习惯记忆 MUST 明确标记为未立项、未实现的产品探索，不得被解释为当前
  公共能力。
- **FR-015**: 当前路线 MUST 排除已经收口为 NO-GO 或取消的 LoCoMo 杠杆，并链接最终
  裁决而不是重复历史推断。
- **FR-016**: 当前论文方向 MUST 采用 prior-art 复核后的“完整负结果史、共同失败机理与
  低成本止损方法”定位；被该定位取代的完整旧提纲必须作为历史材料隔离。
- **FR-017**: 当前产品、路线、竞品和研究文档 MUST 引用评测结果正本，不得各自维护一份
  完整且会独立漂移的分数矩阵。
- **FR-018**: 含有独有实测结果、方法、判据、决策理由，或仍被正式材料引用的负结果、
  诊断、旧决策和设计依据，视为具有审计价值，MUST 保留完整证据并明确 outcome 或现行
  替代入口。
- **FR-019**: 只有在正式规格已包含原设计的用户目标、验收要求和契约引用，原设计不含
  FR-018 定义的独有证据，且仓库内入链为零时，历史设计 MAY 删除；不满足任一条件时
  MUST 保留并可追溯。
- **FR-020**: 现行文档中的原始聊天记录、个人姓名和非必要口语化上下文 MUST 删除，
  同时保留正式问题定义和验收含义。判定标准是：逐字对话、可识别个人姓名、脏话及与
  需求无关的寒暄不得出现在现行文档；只有无法用正式问题陈述保真的一手证据才可保留
  短引文，并必须说明保留理由。
- **FR-021**: 仍被仓库入口引用的旧路径 MUST 继续把读者导向新正本，但不得保留第二份
  正文或快速变化的结论。
- **FR-022**: 所有现行文档 MUST 从统一门户可达；任何保留的历史设计也 MUST 从历史
  索引或正式证据链可达。
- **FR-023**: 验收范围内全部 tracked 文档的本地文件链接和章节深链 MUST 指向存在且
  语义正确的目标；发现范围外文档的链接错误时，MUST 通过范围内的新目标或兼容入口使其
  可解析。若无法在不改写范围外正文的前提下解决，feature MUST 阻塞并请求扩大权限，
  不得以“已报告”代替通过。
- **FR-024**: 文档标题 MUST 保持单一主标题、连续层级和文件内唯一的深链标识。
- **FR-025**: 文档维护规范 MUST 说明新增、更新、引用、归档、删除和人工复核规则。
- **FR-026**: 本 feature MUST 保持产品代码、测试、数据迁移、公共契约、仓库顶层介绍和
  许可内容不变；正式 feature 材料只允许为修复历史设计引用而调整链接。
- **FR-027**: 文档正文 MUST 以中文为主，命令、字段、API、协议、模型和其他专有名词
  保留其标准英文形式。判定标准是：现行文档的标题、章节标题和解释性段落使用中文；
  fenced code、命令、标识符、配置键、标准错误文本、链接目标和专有名词可保留英文。
- **FR-028**: 迁移过程中发现并行修改与目标内容重叠时，工作 MUST 停止在冲突文件，
  明确报告双方意图，不得静默覆盖、回滚或丢弃并行工作。

### Key Entities

- **文档 (Document)**: 一份面向特定读者、回答一个主要问题的内容单元；具有标题、摘要、
  生命周期、受众、维护责任、复核日期、权威主题和关联主题。
- **权威主题 (Canonical Topic)**: 一个稳定的查询意图，例如“当前评测结果”或
  “MCP 接入”；每个主题只能映射到一个现行正本。
- **文档生命周期 (Document Lifecycle)**: 五值互斥分类——稳定现行、变化中的现行、
  未实现提案、历史归档、旧路径迁移；它不表示功能是否出货。
- **功能/实验状态 (Capability or Experiment State)**: 六值互斥分类——默认出货；
  受支持但显式启用；仅评测/诊断保留且无产品承诺；计划中；NO-GO；实现前取消。
- **证据记录 (Evidence Record)**: 支撑结论的完整历史报告、正式规格、评测日志或 verdict；
  可从现行摘要追溯，但不默认参与当前状态回答。
- **导航条目 (Navigation Entry)**: 把读者任务或 AI 查询意图映射到唯一正本的入口。
- **迁移入口 (Relocation Entry)**: 为既有路径保留的兼容入口，只指向新正本，不保存第二份
  内容。

## Success Criteria *(mandatory)*

### Fixed Retrieval Verification Set

以下查询文本、期望权威主题和必须得到的状态结论在验收期间固定不变：

| ID | 固定查询文本 | 期望唯一权威主题 | 必须得到的状态或结论 |
|---|---|---|---|
| Q1 | 如何配置 engram MCP server？ | `mcp-integration` | 现行稳定使用指南 |
| Q2 | engram CLI 支持哪些命令？ | `cli-usage` | CLI 已交付，返回现行命令参考 |
| Q3 | engram 的记忆什么时候抽取，curation 怎么运行？ | `memory-architecture` | curation 为已交付、显式启用能力 |
| Q4 | engram 当前 LoCoMo 和 LongMemEval-S 分数是多少？ | `evaluation-results` | LongMemEval-S 为全量 500 题 |
| Q5 | Feature 013 最终是否出货？ | `experiment-verdicts` | `closed-no-go`，不作为当前路线 |
| Q6 | 记忆新鲜度和状态一致性是否已经实现？ | `current-capabilities` | 尚未实现，并链接提案问题定义 |
| Q7 | SaaS 习惯记忆是不是当前能力？ | `current-capabilities` | 未立项、未实现，并链接产品探索 |
| Q8 | engram 当前论文方向是什么？ | `research-direction` | 完整负结果史、共同失败机理与低成本止损 |

### Measurable Outcomes

- **SC-001**: 100% 的现行文档可从统一门户在不超过两次导航动作内到达；一次导航动作
  定义为选择一个门户分类或跟随一个文档链接，站内搜索不计入动作。
- **SC-002**: 对 Fixed Retrieval Verification Set 的 Q1–Q8，100% 命中表中登记的唯一
  权威主题，并得到登记的状态或结论。
- **SC-003**: 全部仓库内文档链接和章节深链检查结果为 0 个缺失或错误目标。
- **SC-004**: 100% 的现行文档满足 FR-005 的七项必填信息，且生命周期值全部属于
  FR-006 定义的五种语义。
- **SC-005**: 100% 的归档文档明确说明最终 outcome 或现行替代入口；100% 的迁移入口
  只包含导向信息，不复制原正文。
- **SC-006**: 当前文档中关于 LongMemEval-S、CLI、curation、新鲜度、习惯记忆和已收口
  LoCoMo 方向的已知状态矛盾全部清零。
- **SC-007**: 完整当前评测矩阵只维护一份；其他现行文档对分数的引用均能追溯到该正本。
- **SC-008**: 使用 SC-002 登记的八类固定问题执行当前状态检索时，归档、迁移和提案
  材料被误判为已交付事实的次数为 0。
- **SC-009**: 所有保留文档至少有一个导航或证据入链；每份删除的历史设计均有一份正式
  规格覆盖其用户目标、验收要求和契约引用；删除目标的仓库内入链数量为 0。
- **SC-010**: 仓库顶层介绍、许可、产品行为和评测实现相对 feature 开始时保持不变，
  文档重组不引入运行行为变化。
- **SC-011**: 至少两名不同维护者或两个独立审阅过程，依据维护规范对“当前结果、未实现
  提案、已收口实验”三个样例给出完全一致的归类结果。

## Assumptions

- 已确认的文档信息架构设计是本 feature 的上游决策，不再重新讨论目录分层和归档原则。
- “导航动作”按 SC-001 定义计数；检索语料固定为 Fixed Retrieval Verification Set 的
  Q1–Q8 原文，验收期间不临时替换为更容易通过的问题。
- 仓库顶层介绍与许可的并行提交是已接受的入口工作，本 feature 通过兼容入口保持其链接
  有效，而不改写这些文件。
- 现有正式规格、契约、评测日志和 verdict 可作为事实核验依据；历史任务复选框不作为
